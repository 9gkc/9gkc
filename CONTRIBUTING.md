# Contributing to 9gkc projects

Thank you for taking the time to improve a project in the **9gkc** portfolio. Contributions are most useful when they are focused, reproducible, respectful of users, and clear about the value they add.

## Before you start

Please read the target repository’s README, open issues, and security policy before making changes. For security-sensitive work, confirm that the target, scope, and authorization are explicit. Never test against systems, accounts, data, or endpoints that you do not own or have written permission to assess.

## Contribution standards

Use clear names, small cohesive changes, accessible interfaces, and safe handling of DOM, files, credentials, and user data. Do not commit secrets, private keys, personal data, generated dependencies, build output, or local configuration. Prefer the smallest change that solves the stated problem, and update documentation whenever behavior, setup, limitations, or security assumptions change.

## Pull requests

A pull request should explain the problem, the approach taken, the validation performed, and any known limitations. Include screenshots or a short recording when a user-interface change benefits from visual context. If the change affects security boundaries, describe the authorization assumptions and the safeguards used without publishing sensitive details.

## Validation checklist

Before opening a pull request, run the checks documented by the target repository, verify that the relevant user flow works, inspect the final diff for accidental secrets or unrelated files, and confirm that the working tree contains only intentional changes.

## Security reports

Do not report vulnerabilities through a public issue. Follow the private process in [SECURITY.md](./SECURITY.md), and avoid including credentials, API keys, personal data, destructive payloads, or unnecessary proof-of-concept details.

## Code of conduct

Contributors are expected to communicate professionally, welcome good-faith questions, respect different backgrounds and skill levels, and keep discussions focused on improving the project. Harassment, discrimination, threats, and unauthorized security testing are not acceptable.
